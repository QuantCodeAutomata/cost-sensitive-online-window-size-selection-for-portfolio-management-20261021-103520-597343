# Cost-Sensitive Online Window-Size Selection for Portfolio Management

Reproduction of selected experiments from **"Cost-Sensitive Online Window Size
Selection for Portfolio Management"**.

This repository implements the paper's two-level cost-sensitive online
window-size aggregation framework:

1. **Level 1 (experts):** for each candidate window size `j` in a fixed
   expert set `N`, roll a sample mean `mu_hat_j(t)` and sample covariance
   `Sigma_hat_j(t)` over the trailing `j` returns and solve the cost-sensitive
   Mean-Variance problem (Problem 2.1)
   `max_w  mu_hat_j(t)^T w - 0.5 w^T Sigma_hat_j(t) w - c*||w - w_j(t-1)||_1`
   s.t. `w >= 0, 1^T w = 1`, via CVXPY, to obtain the expert's portfolio
   advice `w_j(t)`.
2. **Level 2 (aggregation):** the experts' advices are aggregated online with
   **Hedge** (`alpha=0`) and **Fixed Share** (`alpha>0`) exponential-weighting
   algorithms under the turnover-inclusive Negative-PnL loss
   `ell(w,y) = -w^T y + c*||w - w_prev||_1`, with the learning rate `eta*` and
   sharing rate `alpha*` set from Proposition 3.5, using the switching budget
   `K(T) = floor(T / (log(T) * (log(log(T)))^{1+epsilon}))`.
3. Both the cost-sensitive tracking regret `R_track^c(T,K)` (Problem 2.4,
   Negative-PnL loss) and the stock tracking regret `R_stock(T,K)` (buy-and-hold
   single-stock experts, negative log-return loss) are computed against a
   best-in-hindsight comparator restricted to at most `K` switches, solved by
   dynamic programming.
4. Five benchmark Online Portfolio Selection algorithms are implemented from
   their foundational papers: **UP** (Cover, 1991), **EG** (Helmbold et al.,
   1998), **PAMR** (Li et al., 2012), **CWMR** (Li et al., 2013) and **OLMAR**
   (Li & Hoi, 2014).

## Repository layout

```
src/            experts.py, aggregation.py, regret.py, benchmarks.py,
                metrics.py, pipeline.py (shared end-to-end orchestration)
exp/            exp1 .. exp5, one script per selected experiment
data/           generate_synthetic.py (DGP with regime shift) and
                data_loader.py (QuantX Dataloader market-data path)
tests/          pytest unit tests for every src/ module
results/        all figures, CSV/JSON metrics and RESULTS.md
```

## Experiments

- **exp_1** — Synthetic Market Experiment with Prescribed Regime Shift
  (Section 4.1, Figures 1-2): 32 synthetic stocks, 2,000 days, `j_t` shifts
  from 63 to 5 at day 1000, `N={5,10,21,63}`.
- **exp_2** — Additional Synthetic Experiments (Appendix B.2, Figures 3-4):
  varied regime-shift timing, and an expanded 8-window expert set
  `N={5,10,21,30,41,50,63,126}`.
- **exp_3** — Comparison with OLPS benchmarks on synthetic data (Appendix
  B.3, Figure 5): `R_stock` for Hedge/Fixed Share vs. UP/EG/PAMR/CWMR/OLMAR.
- **exp_4** — Empirical study on DJIA constituents (Appendix B.4, Table 1):
  30 DJIA stocks + BIL, 2021-03-04 to 2024-02-25, `N={5,10,21,30,41,50,63,126}`.
- **exp_5** — Empirical study on S&P 500 constituents (Appendix B.5, Tables
  1/3): a large multi-sector equity universe + BIL, 2020-01-02 to
  2026-08-01 (or the latest tradeable date), same expert set as exp_4.

Market data for exp_4/exp_5 is loaded through the QuantX Dataloader
(`data/data_loader.py`); see that module for the mandatory data-source
comment. Synthetic data for exp_1/exp_2/exp_3 is generated by
`data/generate_synthetic.py`.

## Running

```bash
pip install -r requirements.txt
cp .env.example .env   # fill in DATALOADER_API_KEY / MASSIVE_API_KEY for exp_4, exp_5
./reproduce.sh
```

`reproduce.sh` runs the test suite and then every experiment script in
sequence, writing all artifacts to `results/`.
